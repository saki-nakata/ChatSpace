# ChatSpace 画面設計書

**バージョン:** 1.0
**作成日:** 2026-08-15
**作成者:** Nakata Saki

> 本書は Java/Spring Boot 再設計計画([.plans/java-spring-boot-redesign.md](../.plans/java-spring-boot-redesign.md) §8)に基づき、新フロントエンド(`apps/web-next`)の画面設計の元資料として、現行プロトタイプ(`apps/web`)の実装(`src/App.tsx`・`src/pages/*`・`src/components/**`)を実際に調査して作成した。計画書の方針通り、**ルーティング・画面構成・UIコンポーネント構成はプロトタイプをほぼそのまま踏襲**する(変更点は主に API クライアントの型ソースとリアルタイム通信層)。
>
> **アクセシビリティ要件について**: 本書中の「新規要件」と明記した項目は、プロトタイプには実装が存在せず、Java/Spring Boot 再設計のフロントエンド(`apps/web-next`)で新たに満たすべき要件として追加したものである。それ以外(既存の `aria-label`・`title` 等)はプロトタイプに実装済みの内容をそのまま記載している。

| S-13 | 通知パネル | (S-04 トップバーから開くパネル) | 必要 | パネル |
| S-14 | プロフィール編集モーダル | (S-04 トップバーから開くモーダル) | 必要 | モーダル |

プロトタイプのルーティング定義(`apps/web/src/App.tsx`)は以下の通り。`/`・`/w/:workspaceId` 以下は `RequireAuth` でラップされており、未ログイン(`user` が `null`)の場合は `/login` へリダイレクトする。認証状態の確認中(`status` が `idle`/`loading`)は全画面ローディング表示(`読み込み中...`)を出す。

```
/login                                  → S-01(RequireAuthなし)
/signup                                 → S-02(RequireAuthなし)
/                                       → S-03(RequireAuth)
/w/:workspaceId                        → S-04(RequireAuth、レイアウト)
  ├─ (index)                           → チャンネル/DM未選択状態(EmptyThreadPage)
  ├─ c/:channelId                      → S-05
  └─ dm/:dmId                          → S-06
*(その他すべて)                          → / へリダイレクト
```

新スタック(`apps/web-next`)でもこのルーティング構成をそのまま踏襲する。変更されるのは API クライアントの型ソース(zod → OpenAPI 生成型)とリアルタイム層(Socket.IO → STOMP)のみで、画面・ルーティング自体に変更はない。

## 2. 共通レイアウト

プロトタイプのレスポンシブ対応は Tailwind の `sm` ブレークポイント(640px)による2段階のみであり、TripDiary のような「デスクトップ/タブレット/スマートフォン」の3段階の作り分けは行っていない。**実装の実態に即し、本書でも2段階(640px未満／640px以上)として正確に記載する。**

### 640px 以上(デスクトップ・タブレット共通)

```
+------------------+--------------------------------+
|  サイドバー(w-64) |  トップバー(h-14)                |
|  ワークスペース名  |  [🔍検索] [🔔通知] [アバター]    |
|  ──────────────  +--------------------------------+
|  チャンネル [+]   |                                |
|  # general        |         メインコンテンツ         |
|  🔒 private-ch    |    (チャンネル/DM/未選択状態)    |
|  ──────────────  |                                |
|  DM [+]           |                                |
|  ● bob            |                                |
|  ○ carol          |                                |
|  ──────────────  |                                |
|  メンバー管理      |                                |
+------------------+--------------------------------+
```

サイドバーは常に表示(`sm:static sm:translate-x-0`)。スレッドパネルを開いた場合は、メインコンテンツの右側に幅 384px(`w-96`)の固定パネルとして並置される(メインコンテンツは隠れない)。

### 640px 未満(スマートフォン)

```
+--------------------------------+
| [☰] [🔍検索] [🔔通知] [アバター] |
+--------------------------------+
|                                |
|         メインコンテンツ         |
|                                |
+--------------------------------+
```

サイドバーは既定で非表示(`-translate-x-full`)。トップバー左端の ☰ ボタン(`aria-label="サイドバーを開く"`)をタップすると、画面左からオーバーレイ表示され(`z-40`、背後に半透明の黒背景 `bg-black/40` を敷き、クリックで閉じる)、幅は 640px 以上と同じ 256px(`w-64`)のまま。サイドバー内の閉じるボタン(`✕`、`aria-label="サイドバーを閉じる"`)でも閉じられる。

スレッドパネルを開いた場合、メインコンテンツは非表示(`hidden`)になり、スレッドパネルが画面全幅を占有する(タブレット・PC用の左右並置レイアウトはこの幅では取らない)。

### 共通要素(サイドバー・トップバー)

| 要素 | 内容 |
|------|------|
| サイドバー上部 | 「← ワークスペース一覧」リンク(`/` へ)、ワークスペース名(見出し) |
| サイドバー「チャンネル」セクション | セクション見出し + オーナーのみ表示される「+」ボタン(S-08 起動)。チャンネル一覧(公開チャンネルは `#`、プライベートは `🔒` を先頭に表示)。未読件数がある場合は右端に丸バッジで件数表示。非参加の公開チャンネルをクリックすると自動参加してから遷移する。非参加のプライベートチャンネルはクリックしても何も起きない(招待されていない限り参加できない) |
| サイドバー「ダイレクトメッセージ」セクション | セクション見出し + 常時表示の「+」ボタン(S-11 起動)。DM 一覧。相手のオンライン状態を緑(オンライン)/グレー(オフライン)のドットで表示。未読件数バッジは上記チャンネルと同様 |
| サイドバー下部 | 「メンバー管理」ボタン(S-10 起動)。自分がオーナーの場合は「(オーナー)」を併記 |
| トップバー | 検索ボタン(🔍 検索、S-12 起動)、通知ベル(🔔、未読件数バッジ、S-13 起動/トグル)、プロフィールアバターボタン(画像 or 表示名の頭文字、S-14 起動) |
| ブラウザタブタイトル連動 | チャンネル・DM の未読件数合計が1件以上あるとき `(件数) ChatSpace`(99件超は `99+`)、0件時は `ChatSpace` をタブタイトルに反映する |

## 3. アクセシビリティ要件(新規要件)

計画書([.plans/java-spring-boot-redesign.md](../.plans/java-spring-boot-redesign.md))のドキュメント構成節が明記する通り、キーボード操作・フォーカス移動・モーダルのフォーカストラップ・スクリーンリーダー用ラベルは、`apps/web-next` で**新規に満たすべき要件**として以下の通り定義する。プロトタイプ(`apps/web`)における実装状況もあわせて明記する。

| 項目 | プロトタイプの実装状況 | `apps/web-next` での要件 |
|------|----------------------|--------------------------|
| アイコンのみのボタンへのラベル | 一部実装済み(サイドバー開閉・通知ベル・プロフィールアバター・リアクション追加/トグル・スレッド返信/編集/削除・添付ファイル選択/削除ボタン等に `aria-label`/`title` あり) | 既存分を維持しつつ、未実装箇所(検索ボタン、各モーダルの入力欄、メンション候補ボタン等)にも漏れなく付与する。**新規要件**として全画面を対象に監査する |
| モーダルの `role`/`aria-modal` | 未実装(`Modal.tsx` はただの `div` オーバーレイで `role="dialog"` 等の属性を持たない) | S-08〜S-12・S-14 の各モーダルに `role="dialog"` `aria-modal="true"` `aria-labelledby`(モーダルタイトルを参照)を付与する。**新規要件** |
| モーダルのフォーカストラップ | 未実装(Tab キーでモーダル外の背後要素にフォーカスが移動できてしまう) | モーダル表示中は Tab/Shift+Tab によるフォーカス移動をモーダル内の要素に限定する。**新規要件** |
| モーダルの初期フォーカス・フォーカス復帰 | 一部の入力欄に `autoFocus` はあるが、Escape キーでの閉じる操作・閉じた後のフォーカス復帰は未実装 | モーダルを開いた際は先頭のフォーカス可能要素(既存の `autoFocus` を踏襲)にフォーカスし、Escape キーで閉じられるようにする。閉じた際は起動元のボタン(例: TopBar の検索ボタン)にフォーカスを戻す。**新規要件** |
| 通知パネル(S-13)の開閉 | 背景クリックのみで閉じる。Escape キー非対応、`role` 属性なし | S-08〜S-12 同様のダイアログ相当の扱いとし、Escape キー対応・フォーカス管理を追加する。**新規要件** |
| リアルタイム更新の読み上げ | 未実装(新着メッセージ・通知はスクリーンリーダーに通知されない) | 新着メッセージ・新着通知・タイピングインジケーターの領域に `aria-live="polite"` を設定し、フォーカスを奪わずに読み上げられるようにする。**新規要件** |
| キーボードのみでの一連の操作(チャンネル選択→メッセージ送信→リアクション→スレッド展開) | サイドバー項目・メッセージ入力・送信ボタンはネイティブの `button`/`input`/`textarea` のため基本操作は可能だが、絵文字ピッカー・メンション候補のキーボード操作(矢印キーでの候補移動等)は未実装(Tab/Enter/Escape のみ対応) | メンション候補・絵文字ピッカーに矢印キーでの候補移動を追加する。**新規要件**(Tab/Enter/Escape による最低限の操作自体はプロトタイプに既にあるため維持) |
| フォームの必須項目・エラーのアナウンス | エラーメッセージは `<p>` タグで視覚的に表示されるのみで、`aria-live`・`aria-invalid`・`aria-describedby` との関連付けはない | 各フォームのエラーメッセージ領域に `aria-live="assertive"`、該当入力欄に `aria-invalid`/`aria-describedby` を付与する。**新規要件** |

## 4. 各画面仕様

### S-01 ログイン画面

**URL:** `/login`(認証不要。ログイン済みでも `/login` への直接アクセス自体は許可され、自動リダイレクトはしない)

```
+----------------------------+
|  ChatSpace                 |
|  アカウントにログイン         |
|                            |
|  ユーザーID [テキスト入力]   |
|  パスワード [パスワード入力]  |
|                            |
|  [ログインボタン]           |
|                            |
|  アカウントをお持ちでないですか?|
|  → [新規登録]              |
+----------------------------+
```

| 要素 | 内容 |
|------|------|
| タイトル・サブタイトル | 「ChatSpace」+「アカウントにログイン」をカード上部に表示 |
| ユーザーID | テキスト入力。`autoFocus`・`required` |
| パスワード | `type="password"`・`required` |
| ログインボタン | `useAuthStore().login(userId, password)` を呼び出し、成功時 `/` へ `replace` 遷移。送信中は「ログイン中...」に文言変更しボタンを disable |
| エラー表示 | 失敗時、`ApiError` のメッセージ(なければ「ログインに失敗しました。」)をフォーム下部に赤字表示 |
| 新規登録リンク | カード下部に配置。`/signup` へ遷移 |

### S-02 新規登録画面

**URL:** `/signup`(認証不要)

```
+----------------------------+
|  ChatSpace                 |
|  新規アカウント登録(メール認証は不要です) |
|                            |
|  ユーザーID [テキスト入力]   |
|  表示名 [テキスト入力]       |
|  パスワード [パスワード入力]  |
|                            |
|  [登録するボタン]           |
|                            |
|  既にアカウントをお持ちですか?|
|  → [ログイン]              |
+----------------------------+
```

| 要素 | 内容/バリデーション |
|------|------|
| ユーザーID | 必須。`USER_ID_REGEX`(`/^[a-zA-Z0-9_.-]{3,20}$/`、英数字・`_`・`.`・`-` のみ、3〜20文字)。placeholder「例: taro_yamada」 |
| 表示名 | 任意。未入力時はユーザーIDをそのまま表示名として使用。placeholder「例: 山田太郎」 |
| パスワード | 必須。クライアント側で8文字以上をチェック。placeholder「8文字以上」 |
| 登録するボタン | `useAuthStore().signup(userId, password, displayName || userId)` を呼び出し、成功時 `/` へ `replace` 遷移。送信中は「登録中...」表示 |
| エラー表示 | クライアント側バリデーション不合格時、および `ApiError` 発生時に赤字表示 |
| ログインリンク | `/login` へ遷移 |

### S-04 ワークスペースシェル(サイドバー・トップバー)

**URL:** `/w/:workspaceId`(認証必要。子ルートを持つレイアウト画面)

サイドバー(Sidebar)・トップバー(TopBar)・メインコンテンツ(`Outlet` — S-05/S-06/未選択状態のいずれか)から構成される。共通要素の詳細は「2. 共通レイアウト」を参照。

**チャンネル/DM 未選択状態**: 初期表示時(`/w/:workspaceId` に直接アクセスした場合など)は、メインコンテンツ領域に「左のサイドバーからチャンネルまたはDMを選択してください。」という案内文のみを中央表示する(`EmptyThreadPage`)。

| 要素 | 内容 |
|------|------|
| ワークスペース読み込み | 画面遷移時にワークスペース情報・チャンネル一覧・DM一覧を取得(`enterWorkspace`)、完了するまで `Outlet` を描画しない |
| 通知・プレゼンス初期化 | マウント時に通知一覧取得(`loadNotifications`)とオンラインユーザー一覧取得(`workspaceApi.presence`)を実行。ブラウザ通知の許可も要求する |
| リアルタイムイベント購読 | チャンネル作成/削除、ワークスペースからの自分のキック(→ `/` へリダイレクト)、メッセージ作成(未読数更新)、通知受信(ストア反映 + ブラウザ通知表示)、DM スレッド作成、プレゼンス更新、をソケットで購読する(新スタックでは STOMP に置き換え) |

---

### S-05 チャンネル画面

**URL:** `/w/:workspaceId/c/:channelId`(認証必要。チャンネルの現メンバーのみ実データが見える)

```
+--------------------------------------------------+
|  # general               [最新に戻る] [メンバー] [チャンネル削除(オーナー)] |
+--------------------------------------------------+
|  ── 2026年8月15日 ──                               |
|  [avatar] alice  10:03                            |
|  本文(Markdownレンダリング)                          |
|  [👍 2] [🎉 1] [+😀]                                |
|  3件の返信を表示                                     |
|  ── ここから未読 ──                                  |
|  [avatar] bob  10:20                               |
|  ...                                               |
+--------------------------------------------------+
|  ○○ が入力中...                                     |
|  [📎] [メッセージ入力欄 (Markdown / Shift+Enter / @メンション)] [送信] |
+--------------------------------------------------+
```

| 要素 | 内容 |
|------|------|
| ヘッダー | チャンネル名(公開は `#`、プライベートは `🔒` プレフィックス)。検索/通知経由のジャンプ後は「最新に戻る」ボタンを表示。「メンバー」ボタン(S-09 起動)、ワークスペースオーナーのみ「チャンネル削除」ボタン(ブラウザ標準の `confirm()` ダイアログで確認後、削除して `/w/:workspaceId` へ遷移) |
| メッセージ一覧(MessageList) | **上方向無限スクロール + 仮想化 + WebSocket新着append方式(レビュー指摘により詳細化)。** 上端まで80px以内スクロールで過去ログを自動読み込み(50件単位、`(createdAt, id)` カーソル)。表示件数が多くなるため**仮想化リスト**(画面外の行はDOMを保持しない)で描画する。過去ログ取得(prepend)前に画面先頭に見えているメッセージIDとその画面上の位置を記録しておき、prepend後に同じメッセージが同じ画面位置に来るようスクロール位置を復元する(Markdown・画像・動画の遅延読み込みによる高さ変化にも追従して再調整する)。**新着メッセージ受信時の挙動**: 画面最下部から一定距離以内(例: 200px以内)にいる場合のみ自動的に最下部までスクロールする。最下部から離れた位置で過去ログを閲覧中の場合は自動スクロールせず新着を蓄積し、「↓ 新着メッセージ N件」ボタンを表示する(押下で最下部へ移動し件数表示をクリア)。ただし**自分が送信したメッセージは現在位置に関わらず常に最下部へスクロールする**。日付区切り線(前メッセージと日付が異なる場合)、未読区切り線(このスコープを開いた瞬間の既読位置を基準に固定表示。「ここから未読」の赤線)、読み込み中/「これより過去のメッセージはありません」の状態表示、0件時の空状態メッセージ、検索・通知ジャンプ時のハイライト表示(該当メッセージを画面中央にスクロールし、琥珀色背景を1秒かけてフェードアウト)。ジャンプ後にさらに古い/新しい方向へスクロールした場合は、`context` APIが返す `olderCursor`/`newerCursor`(メッセージング機能定義書§3.6)を使って通常の一覧取得APIへ継続する |
| メッセージ本体(MessageItem) | アバター(画像 or 表示名頭文字)、表示名、送信時刻、編集済みの場合「(編集済み)」表示。削除済みメッセージは本文の代わりに「このメッセージは削除されました」を斜体表示。本文は Markdown → サニタイズ済み HTML でレンダリング(`img` タグ除外)。画像/動画添付はインライン表示(最大高さ 56)。自分のメッセージのみホバー時に ✏️ 編集(インライン `textarea` へ切替、保存/キャンセル)・🗑️ 削除アイコンを表示。返信が1件以上ある場合「N件の返信を表示」リンクで S-07 を開く。ホバー時に 💬 スレッド返信アイコンも表示 |
| リアクション(ReactionBar) | 付与済みリアクションを絵文字+件数のチップで表示(自分が押した絵文字は強調表示、`aria-pressed` 付き)。チップクリックでトグル。「+😀」ボタンで16種のクイック絵文字グリッド、または任意の絵文字(最大8文字)を入力するフォームを開く |
| タイピングインジケーター | 自分以外のユーザーが直近4秒以内にタイピングイベントを送っている間、「○○(、△△)が入力中...」を表示 |
| メッセージ入力(MessageComposer) | 📎 添付ボタン(画像 png/jpeg/gif/webp・動画 mp4/webm、複数選択可、アップロード即時実行)、添付プレビュー(サムネイル/🎬アイコン + ファイル名 + 削除✕)、`@` 入力でメンション自動補完(対象チャンネルの現メンバーのみを候補に、ユーザーID前方一致 or 表示名部分一致で最大6件表示、Tab/Enter で確定、Escape で閉じる)、テキストエリア(Enter送信・Shift+Enter改行、2秒間隔でタイピングイベント送信)、送信ボタン |
| リアルタイム更新 | メッセージ作成/更新/削除、リアクション更新をソケットで購読し即時反映 |
| 検索・通知からのジャンプ | URL クエリ `?highlight=<messageId>&reply=<replyId>` を受け取り、該当メッセージ周辺の文脈を取得してハイライト表示する。`reply` 指定時は親メッセージを軸にスレッドパネル(S-07)を自動的に開き、該当返信をハイライトする |

### S-07 スレッドパネル

**表示条件:** S-05・S-06 のいずれかで、メッセージの「N件の返信を表示」リンクまたは 💬 アイコンをクリックしたとき(共通コンポーネント `ThreadPanel`)。専用URLは持たない(検索/通知ジャンプ時はクエリパラメータ経由で自動的に開く)。

```
+--------------------------+
|  スレッド            [✕]  |
+--------------------------+
|  (親メッセージ)            |
+--------------------------+
|  (返信一覧、親と同じ表示形式)|
|                          |
+--------------------------+
|  [返信入力欄]      [送信]  |
+--------------------------+
```

| 要素 | 内容 |
|------|------|
| 表示位置 | 640px 以上: メインコンテンツ右側に幅384pxで並置。640px未満: メインコンテンツを非表示にして全幅表示 |
| ヘッダー | 「スレッド」ラベル + ✕ 閉じるボタン(`aria-label="スレッドを閉じる"`) |
| 親メッセージ | S-05 と同じ `MessageItem` 表示(ただしスレッド返信ボタンは非表示) |
| 返信一覧 | **初期表示は古い順に20件。末尾に「さらに20件の返信を読み込む」ボタン(残件数を正確に算出できる場合は「さらにN件」、できない場合は「さらに返信を読み込む」)を表示する(レビュー指摘により確定、メッセージング機能定義書§3.4参照)。** WebSocket経由の新着返信は一覧の末尾に追加する。検索/通知ジャンプ時は該当返信をハイライト表示(ハイライト対象が未読み込みの場合は追加取得してから表示) |
| 返信入力 | `MessageComposer`(placeholder「スレッドに返信...」、メンション自動補完なし、タイピングイベント送信なし) |
| リアルタイム更新 | 親メッセージ・各返信の作成/更新/削除・リアクション更新をソケットで購読 |

### S-12 検索モーダル

**起動元:** S-04 トップバーの「🔍 検索」ボタン

```
+----------------------------+
|  メッセージ検索          [✕] |
|                            |
|  [キーワード入力]     [検索] |
|  自分が参加しているチャンネル・|
|  DMの範囲のみを検索します。   |
|                            |
|  結果1: alice  3分前         |
|  本文プレビュー(2行まで)      |
|  結果2: ...                 |
+----------------------------+
```

| 要素 | 内容 |
|------|------|
| 検索フォーム | キーワード入力(`autoFocus`) + 「検索」ボタン。空文字では送信しない |
| 検索範囲の注記 | 「自分が参加しているチャンネル・DMの範囲のみを検索します。」を常時表示 |
| 検索結果 | 送信者表示名・相対時刻・本文プレビュー(2行で `line-clamp`)をカード状に一覧表示 |
| 追加読み込み(レビュー指摘により確定) | **「さらに検索結果を表示」ボタンを基本とし、ボタン押下後はスクロールでも追加取得できる併用方式**とする(完全な無限スクロールのみにしない。モーダル内でのキーボード操作・終端到達のわかりやすさを優先)。件数表示は追加の `COUNT(*)` を発行せず、`nextCursor` の有無から組み立てる(`nextCursor != null` の間は「50件以上」「100件以上」のように「以上」表記、`nextCursor == null` になった時点で確定件数「150件」等を表示。検索機能定義書§3.2参照) |
| 結果クリック | モーダルを閉じ、該当メッセージのチャンネル/DMへ `?highlight=<id>` 付きで遷移。スレッド返信がヒットした場合は親メッセージを `highlight` に、返信自体を `reply` に指定してスレッドパネル(S-07)を自動的に開く |
| 空状態 | 検索実行後0件の場合「該当するメッセージが見つかりませんでした。」を表示 |

| ヘッダー | 「通知」ラベル + 「すべて既読にする」ボタン |
| 通知種別バッジ | メンション/DM/チャンネル招待/ワークスペース招待/スレッド返信の5種を日本語ラベルで表示 |
| 通知一覧(レビュー指摘によりページネーション仕様を詳細化) | 種別バッジ + 相対時刻 + 通知本文。未読の通知は背景色を強調表示。新しい順に表示し、**パネル下端に近づいたタイミングで次の50件をパネル内無限スクロールで取得する**(取得中は同一カーソルへの二重リクエストを防止するフラグを持つ)。既読化操作は一覧の並び順・表示位置を変更しない(既読になっても消えたり動いたりしない)。WebSocket経由の新着通知は一覧の**先頭**に追加する。パネルを閉じても同一セッション中(タブを閉じるまで)は取得済み一覧とスクロール位置を保持し、再度開いた際に再取得しない(通知機能定義書§7参照) |
| 通知クリック | 未読なら既読化した上でパネルを閉じ、対象チャンネル/DMへ遷移。スレッド返信通知はメッセージへの `highlight`/`reply` クエリを付与し S-07 を自動的に開く |
| 空状態 | 通知が0件の場合「通知はありません。」を表示 |
