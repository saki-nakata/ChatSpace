# チャンネル機能定義書

**バージョン:** 1.0
**作成日:** 2026-08-15

> 本ドキュメントは `.plans/java-spring-boot-redesign.md`(以下「計画書」)§3「認証・認可レイヤー」を正式文書化したものである。移植元は `apps/api/src/routes/channels.ts`・`apps/api/src/lib/authz.ts`。

---

## 1. 機能概要

チャンネルはワークスペース配下のテキストチャットの単位で、**パブリック**(誰でも自主参加可能)と**プライベート**(招待制、非メンバーには存在も非表示)の2種類を持つ。

- チャンネルの新規作成(オーナー限定)、一覧取得
- パブリックチャンネルへの自主参加(join)
- プライベートチャンネルへのオーナーによる招待
- 既読管理、メンバー一覧・退出/キック
- チャンネル削除(オーナー限定)
- 認可は `ChannelAuthorizationService`(プロトタイプの `authz.ts` の `requireChannelMember` を移植)が担う

---

## 2. ユーザーストーリー

| ID | ストーリー |
|----|-----------|
| US-01 | オーナーとして、パブリックまたはプライベートのチャンネルを作成したい |
| US-02 | ワークスペースメンバーとして、パブリックチャンネルの一覧を見て自由に参加したい |
| US-03 | ワークスペースメンバーとして、招待されていないプライベートチャンネルの存在を知りたくない |
| US-04 | オーナーとして、プライベートチャンネルに特定のメンバーを招待したい |
| US-05 | チャンネルメンバーとして、既読位置を更新したい |
| US-06 | チャンネルメンバーとして、自分の意思でチャンネルから退出したい |
| US-07 | オーナーとして、問題のあるメンバーをチャンネルから強制退出させたい |
| US-08 | オーナーとして、不要になったチャンネルを削除したい |

---

## 3. 機能詳細

### 3.1 チャンネル作成(オーナー限定)

- 入力:チャンネル名(`^[a-zA-Z0-9_-]{1,50}$`)、種別(`PUBLIC`/`PRIVATE`)、(プライベートの場合)初期メンバーのユーザーID(ハンドル)配列
- 処理:
  1. ワークスペースオーナー権限チェック
  2. 同一ワークスペース内で同名チャンネルが存在すれば409 Conflict(`@@unique([workspaceId, name])`)
  3. `PRIVATE` かつ `memberUserIds` 指定時、ハンドルをユーザーテーブルで解決し、かつ**ワークスペースメンバーであるユーザーのみ**を初期メンバーとして絞り込む(非メンバーを紛れ込ませない)
  4. 作成者は常に初期メンバーに含まれる
  5. ワークスペース全体へチャンネル作成イベントを配信(`/topic/workspaces.{workspaceId}`)

### 3.2 チャンネル一覧

- ワークスペースメンバーのみアクセス可
- 返す集合は「全パブリックチャンネル」∪「自分がメンバーであるチャンネル(プライベート含む)」。**非メンバーのプライベートチャンネルは一覧に一切出現しない**
- 各チャンネルに自分の参加状態(`isMember`)、未読数(`unreadCount`、自分以外の投稿者による `deletedAt IS NULL` のメッセージのうち `lastReadAt` より新しいもの)を含める

### 3.3 パブリックチャンネルへの自主参加(join)

- ワークスペースメンバーであることのみを要求(チャンネルへの事前招待は不要)
- 対象チャンネルが存在しない、またはワークスペースが一致しない場合は404
- **対象がプライベートの場合も404とする(レビュー指摘により403から修正)**: 当初403(「プライベートチャンネルは招待された場合のみ参加できます」)としていたが、これだと非メンバーが既知/推測したチャンネルIDでjoinを試みた際に「403=存在する」「404=存在しない」という応答の違いから、一覧に出ていないはずのプライベートチャンネルの存在を確認できてしまう(§4「プライベートチャンネルの存在秘匿」方針と矛盾する)。この矛盾を解消するため、**非メンバーによるプライベートチャンネルへのjoin試行は、存在しないチャンネルへのアクセスと同じ404を返す**よう統一する(403は「本人が既に見えている・アクセスできるリソースに対する権限不足」の場合にのみ用いる、という本プロジェクト全体の404-not-403方針に揃える)
- 既に参加済みの場合は冪等(upsert、200)

### 3.4 既読更新

- チャンネルメンバーのみ実行可。`ChannelMember.lastReadAt` を現在時刻に更新する

### 3.5 プライベートチャンネルへの招待(オーナー限定)

- 入力:招待するユーザーID(ハンドル)
- CLAUDE.md の「オーナー限定操作(キック、チャンネル追加・削除、招待)」の方針に合わせ、**チャンネル単位の招待もワークスペースオーナーのみ**が実行できる(チャンネルメンバー自身による招待は不可)
- 処理:
  1. ワークスペースオーナー権限チェック
  2. チャンネルが対象ワークスペースに存在することを確認(不一致は404)
  3. 招待対象ハンドルをユーザーテーブルで解決(存在しなければ404)
  4. **対象ユーザーがワークスペースメンバーであることを確認**(非メンバーなら404「指定されたユーザーはこのワークスペースのメンバーではありません。」)。ワークスペースに属さないユーザーをいきなりチャンネルへ追加することはできない
  5. `ChannelMember` を作成(冪等)し、通知(`CHANNEL_INVITE`)を送信

### 3.6 チャンネル退出/キック

- 呼び出し元は少なくともチャンネルメンバーであること(非メンバーは404)
- 対象ユーザーが呼び出し元自身でない場合は、追加で**ワークスペースオーナー権限**が必要(403)
- 削除後、対象ユーザーを購読からも強制退出させる(リアルタイム経路、詳細は `リアルタイム通信機能定義書.md`)

### 3.7 メンバー一覧

- チャンネルメンバーのみアクセス可。参加日時昇順で全メンバー(ユーザー情報・参加日時)を返す

### 3.8 チャンネル削除(オーナー限定)

- ワークスペースオーナー権限チェック
- チャンネルが対象ワークスペースに存在することを確認(不一致は404)
- 削除は物理削除(`Message` 等の子リソースはカスケード削除、`onDelete: Cascade`)
- ワークスペース全体へ削除イベントを配信

## 4. 使用 API

| Method | エンドポイント | 説明 | 認証 |
|--------|--------------|------|------|
| POST | `/workspaces/{workspaceId}/channels` | チャンネル作成 | 必要(オーナー限定) |
| GET | `/workspaces/{workspaceId}/channels` | チャンネル一覧 | 必要(ワークスペースメンバー) |
| POST | `/workspaces/{workspaceId}/channels/{channelId}/read` | 既読更新 | 必要(チャンネルメンバー) |
| POST | `/workspaces/{workspaceId}/channels/{channelId}/join` | パブリックチャンネルへの自主参加 | 必要(ワークスペースメンバー) |
| POST | `/workspaces/{workspaceId}/channels/{channelId}/members` | メンバー招待 | 必要(オーナー限定) |
| GET | `/workspaces/{workspaceId}/channels/{channelId}/members` | メンバー一覧 | 必要(チャンネルメンバー) |
| DELETE | `/workspaces/{workspaceId}/channels/{channelId}/members/{targetUserId}` | 退出/キック | 必要(本人、または他人はオーナー限定) |
| DELETE | `/workspaces/{workspaceId}/channels/{channelId}` | チャンネル削除 | 必要(オーナー限定) |

## 5. バリデーション仕様

| 項目 | 制約 | 備考 |
|------|------|------|
| チャンネル名(`name`) | 必須・`^[a-zA-Z0-9_-]{1,50}$` | 英数字・`_`・`-` のみ、1〜50文字。ワークスペース内で一意 |
| 種別(`type`) | 必須・`PUBLIC` または `PRIVATE` の enum | Java 側は `ChannelType` enum(`@Enumerated(EnumType.STRING)`) |
| 初期メンバー(`memberUserIds`) | 任意・ユーザーID(ハンドル)の配列 | `PRIVATE` の場合のみ意味を持つ。ワークスペース非メンバーは自動的に除外される |
| 招待対象ユーザーID | 必須(空文字不可) | ハンドルとして解決 |
| 退出/キック対象ユーザーID | パスパラメータ、必須 | 内部ユーザーID |

## 6. セキュリティ仕様

| 項目 | 仕様 |
|------|------|
| チャンネルメンバー判定 | `ChannelAuthorizationService.requireChannelMember(channelId, userId, workspaceIdOrNull)` — チャンネルが存在しない、`workspaceId` 不一致、または `ChannelMember` レコードが無い場合はいずれも **404**(パブリック・プライベートの区別なく、非参加者には「チャンネルが見つかりません」で統一する) |
| **チャンネル可視性の受入条件**(最重要) | ・**パブリックチャンネル**:ワークスペースメンバー全員の一覧(`GET /channels`)に表示され、誰でも `join` で自主参加できる。ただしメッセージ等の閲覧には `ChannelMember` レコード(参加)が必要であり、一覧に出ていても未参加の間はメッセージにアクセスできない(404)<br>・**プライベートチャンネル**:非メンバーの一覧には**一切表示されない**(存在も伏せる)。オーナーによる招待でのみ参加でき、非メンバーが直接 `channelId` を指定してアクセスしても404 |
| **404-not-403 方針** | 非メンバー(パブリック・プライベート問わず)によるアクセスは404。メンバーではあるがオーナー限定操作を試みた場合は403。**プライベートチャンネルに対する`join`試行(非メンバーによる直接API呼び出し)も、存在を隠すため403ではなく404とする**(レビュー指摘により修正。403だと「存在するが操作不可」と「存在しない」を応答コードで区別できてしまい、一覧非表示による存在秘匿の意図と矛盾するため) |
| confused-deputy対策 | `workspaceId`/`channelId` の不一致(URLの `workspaceId` と実際のチャンネルの所属ワークスペースが異なる)は常に404として扱う。`requireChannelMember` が `workspaceId` を受け取った場合に必ず照合する |
| 招待時のワークスペースメンバーシップ検証 | チャンネルへの招待は、対象ユーザーが**現在ワークスペースメンバーであること**を必須とする(非メンバーをいきなりチャンネルに追加できない) |
| オーナー限定操作の一覧 | チャンネル作成・招待・キック・削除の4操作。CLAUDE.md の既存方針を継続 |

---

## 7. 制約・前提条件

- チャンネル名はワークスペース内で一意(`@@unique([workspaceId, name])`)。削除済みチャンネルの名前は再利用可能(物理削除のため)
- プライベートチャンネルのメンバー追加はオーナー限定であり、既存メンバーが他のメンバーを追加する機能は無い
- チャンネル削除は物理削除であり、投稿されたメッセージ・添付ファイル参照・リアクション等もカスケード削除される(ソフトデリートではない)

---

## 8. 対象外仕様

| 機能 | 理由 |
|------|------|
| チャンネル名の変更 | スコープ外(プロトタイプにも無い) |
| チャンネルのアーカイブ(削除以外の非表示化) | スコープ外 |
| チャンネル種別の後からの変更(PUBLIC⇔PRIVATE) | スコープ外 |
| 一般メンバーによるチャンネル招待 | オーナー限定方針により対象外 |

## 9. テスト

`test/authorization.test.ts` からポートするもの(フェーズ2-3):

| # | テストケース | 確認内容 |
|---|------------|---------|
| 1 | プライベートチャンネルの非可視性 | 非メンバーの一覧取得でプライベートチャンネルが含まれないこと、直接IDを指定してもメッセージ取得等が404になること |
| 2 | workspaceId/channelId 不一致時の404 | 別ワークスペースの `channelId` を指定した場合に404になること |
| 3 | オーナー限定操作の403 | 一般メンバーがチャンネル作成・招待・キック・削除を試みると403になること |

新規に追加する受け入れテスト:

| # | テストケース | 確認内容 |
|---|------------|---------|
| 4 | パブリックチャンネルの自主参加可 | ワークスペースメンバーが招待なしで `join` に成功すること |
| 5 | プライベートチャンネルへのjoin拒否 | プライベートチャンネルへ `join` を試みると403になること |
| 6 | 招待時の非ワークスペースメンバー拒否 | ワークスペースに属さないユーザーをチャンネルへ招待しようとすると404になること |
| 7 | 同名チャンネルの409 | 同一ワークスペース内で同名チャンネルを作成しようとすると409になること |
