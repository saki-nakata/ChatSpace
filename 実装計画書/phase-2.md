## フェーズ-2 — 技術検証スパイク

**状態: ✅ 完了(2026-08-15)**

設計判断の根拠になっている技術的な未検証事項のうち、後戻りコストが大きいものを先に検証した。`pg_bigm` がローカルでは使えてもマネージド環境(Render)では使えなかった、という一度の手戻りを踏まえ、「ローカルで確認できたから良し」とはせず、公式ドキュメント・実際のサーバーレスポンスで裏取りする方針を徹底した。

### (a) 検索拡張の対応状況(Render公式ドキュメント調査)

- `pg_trgm` は Render 公式ドキュメントで PostgreSQL 13以降のサポート対象拡張として明記されていることを確認
- `pg_bigm` は Render のサポート対象拡張一覧に存在しないことを確認 → **`pg_trgm` + `ILIKE` を採用**する根拠となった(検索機能定義書.md参照)

### (b) STOMP基本疎通・セッション取得の確認

- フェーズ0でのビルド検証時に、Spring Boot起動・Tomcat起動までは確認済み。STOMPエンドポイントの実装自体はフェーズ4で行うため、`WebSocketHandlerDecoratorFactory`によるセッション捕捉の実地検証はフェーズ4着手時に改めて行う

### (c) 使用バージョンの確定

フェーズ0の実施の中で確定した(詳細は [phase0.md](phase0.md) 参照):

- Java 21(LTS)
- Spring Boot 4.1.0(RELEASE)
- Gradle 9.7.0(Wrapper)
- PostgreSQL 16(ローカル。Render提供バージョンとの整合は実インスタンス作成時に再確認)

### (d) Render の WebSocket サポート状況

Render公式ドキュメントで確認:

- Render Web Service はパブリックインターネットからのWebSocket接続を受付可能
- **アイドルタイムアウトは固定値なし**(ただしデプロイ・再起動時に強制切断される)
- ハートビート間隔の公式推奨値はなく、「ping/pongによる定期的なkeepaliveと指数バックオフ付き再接続ロジック」が一般的なベストプラクティスとして案内されている → フェーズ4のクライアント側 `heartbeatIncoming`/`heartbeatOutgoing`/`reconnectDelay` 設定はこの指針に沿う

### 未実施・繰り越し事項

- **Render実インスタンスでの `pg_trgm` EXPLAIN確認(大量データでの検証)**: Renderアカウントでの実インスタンス作成が必要なため未実施。フェーズ6(検索実装)着手前、またはユーザーがRenderインスタンスを用意した時点で改めて実施する
- ローカルDocker上のPostgreSQL 16では、少量データでの動作確認(pg_trgm拡張の有効化、日本語2文字クエリでの正しいマッチ結果)は実施済み(フェーズ0で実施、[phase0.md](phase0.md)参照)。ただしテーブルサイズが小さすぎるため、EXPLAINでのインデックス使用有無の意味のある検証はできていない
