### 作成方法

6つのエージェントに分担させ並行作成した(各エージェントは `.plans/java-spring-boot-redesign.md` とプロトタイプの該当実装ファイルを一次情報源として読み込んだ上で執筆)。特に画面設計書・画面遷移図の担当エージェントは、プロトタイプ(`apps/web/src/`)の実コンポーネントを実際に読み込んで正確な仕様を起こした(憶測で書いていない)。

### その後の複数回レビュー対応

作成後、複数のレビュー(Sol等)で以下のような文書間の不整合・誤りが指摘され、修正済み:

- 通知種別 `THREAD_REPLY` がDB設計書のCHECK制約から漏れていた → 追加
- `messages` テーブルのスコープ制約が `OR` で両方NOT NULLを許容してしまっていた → `XOR`相当に修正
- プライベートチャンネルへの `join` 試行が403を返し、存在秘匿方針と矛盾していた → 404に統一
- bcryptの上限が「72文字」と「72バイト」で混同されていた → UTF-8バイト長での検証に修正
- 削除済みメッセージの表示方針が文書間で矛盾していた(一覧からの完全除外 vs tombstone表示) → tombstone方式(検索のみ除外)に統一
- スレッド返信の階層制限(2階層目の禁止)が未定義だった → APIレベルでのバリデーションを追加
- 通知一覧のページネーション方式が未確定だった → `(createdAt, id)`複合カーソル・最大50件に確定
- Render無料インスタンスと永続ディスクの前提が矛盾していた → 本番構成は有料プラン必須と明記
- `.plans/`がGit管理対象外であることの注記が不足していた → 要件定義書に一元的な注記を追加

さらにその後、ユーザー指示によりページネーション仕様(スレッド返信の初期20件+追加読み込み、around API の双方向カーソル化、検索モーダルの「さらに表示」方式、通知パネルの無限スクロール詳細、新着メッセージ制御)を機能定義書・画面設計書に反映した。
