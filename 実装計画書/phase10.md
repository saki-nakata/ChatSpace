- [x] 未読区切り線(スコープを開いた瞬間の既読位置を基準に固定表示) — `ChatView.tsx`に実装。
  - **2026-08-18修正(PR #6レビュー対応):** 当初はサイドバーの`unreadCount`(件数)をpropとして受け取る設計だったが、
    (1) 既読化PATCHがサイドバー側の初回GETより先にバックエンドへ到達すると、そのGET自体が既に0件を返すという
    コンポーネント間の競合、(2) `unreadCount`はスレッド返信も数え自分の投稿・削除済みを除外するのに対し
    `messages`はトップレベルのみで自分の投稿・tombstoneも含むという母集団の不一致、の2つの不具合があった。
    件数ベースをやめ、`GET /messages`(初回ページ)のレスポンス自体に呼び出し元の`lastReadAt`(タイムスタンプ)を
    含める設計に変更し、`messages.find(m => createdAt > lastReadAt)`による純粋な導出に置き換えた。既読化APIと
    同一リクエストの応答から取得するため、コンポーネント間の競合が構造的に発生しなくなった。
- [x] 検索結果・通知からのジャンプ・ハイライト(該当メッセージを画面中央にスクロールし背景色フェードアウト。スレッド返信もジャンプ対象、S-07を自動的に開く)。**フェーズ9-D/9-Fの既知の制約(読み込み済み範囲外のスレッドへジャンプできない)を解消した。** バックエンドの`GET /messages/{id}/context`(前後ウィンドウ+`hasOlder`/`hasNewer`を返す、フェーズ8時点で実装済みだが未使用だったエンドポイント)を新規に呼び出し、対象が未読み込みの場合はメッセージ配列を丸ごと入れ替えてVirtuosoを再マウントする(`firstItemIndex`を初期値に戻し、`initialTopMostItemIndex`で直接ジャンプ先を指定。命令的`scrollToIndex`は再マウント直後だとVirtuoso自身の初期配置に負けて意図した位置に着地しないことを実機確認で発見し、propでの直接指定に変更した)。ウィンドウとライブ末尾の間にギャップが残る場合(`hasNewer`)はリアルタイム新着の追記を止め、「ジャンプ中・最新のメッセージに戻る」導線で復帰させる設計とした。
  - **2026-08-18追記(PR #6レビュー対応):** 21件目以降のスレッド返信へのジャンプが機能していなかった不具合を修正した。バックエンドに`GET .../replies?around=<返信ID>`(対象返信を含む窓を`createdAt DESC`+`LIMIT REPLY_JUMP_MAX_SIZE(300)`で取得しサービス層で反転して返す。対象自身は境界条件のため上限に関わらず必ず含まれる)を新設した。**300件を超えるスレッド返信は現実的な使用範囲では起きない想定で、上限より前の返信への到達手段(hasOlder相当のAPI拡張・ThreadPanel側の後方ページング)は今回のスコープ外とする明示的な割り切り**(対象自身は必ず表示できるため、機能自体は成立する)。あわせて、ジャンプ中に自分が投稿すると`upsertMessage`のギャップガードにより投稿が消える不具合(A-1)、「最新に戻る」で開いていたスレッドパネルが無言で閉じる不具合(A-4、`messages`配列の丸ごと差し替えが`openThreadMessage`の前提を壊していた)も修正した。
- [x] タブタイトルの未読件数 — `useUnreadTabTitle`(新規)。サイドバーの未読バッジと同じ「現ワークスペース内の未読メッセージ数」(チャンネル+DMの`unreadCount`合計)を使う(通知ベルの`unreadCount`はメンション・招待等の別概念のため混ぜない)。
