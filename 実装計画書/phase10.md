## フェーズ10 — UX拡張

**状態: ✅ 完了**

必須機能要件そのものではないが、プロトタイプで実際の使用感を確認しながら価値が確認できた拡張機能を実装する(README.md「上記の要件に加えて」節参照)。

**2026-08-17 棚卸し**: 当初の対象7項目のうち4項目はフェーズ9の実装過程で先行実装済みだったため完了扱いとした(詳細は各項目の注記を参照)。実質的な残作業だった未読区切り線・検索/通知ジャンプ・タブタイトル未読件数の3項目、および任意機能のブラウザ通知(簡易版)を実装し、`apps/api-java`+`apps/web-next`を起動してブラウザ(Playwright)で動作確認済み(60件超のメッセージ・別ユーザーからの新着・検索/通知経由のジャンプ・デスクトップ通知トグル・タブ幅390px/デスクトップ幅の両方を確認、コンソールエラーなし)。

### 実装対象

- [x] タイピングインジケーター表示(フェーズ4で実装済みのSTOMPイベントをUIに反映) — フェーズ9-Bで先行実装済み(`ChatView.tsx`の`typingUserIds`、2秒スロットリング送信・3秒自動失効)
- [x] オンライン/オフラインのプレゼンス表示(フェーズ4・9-Dで実装済みの基盤をUIに反映) — フェーズ9-A(ワークスペース単位のオンライン人数)・9-E S-10(`WorkspaceMembersModal`でメンバー個別のオンライン/オフラインドット表示)で先行実装済み
- [x] スレッド返信の通知UI(フェーズ5で実装済みの`THREAD_REPLY`通知をパネルに反映) — フェーズ9-D S-13通知パネルで先行実装済み(`NotificationPanel.tsx`)
- [x] ワークスペースからの自主退出(フェーズ2で実装済みAPIをUIから呼べるようにする) — フェーズ9-E S-10で先行実装済み(`WorkspaceMembersModal.tsx`の`handleLeave`、`workspaceApi.leave`)
- [x] 未読区切り線(スコープを開いた瞬間の既読位置を基準に固定表示) — `ChatView.tsx`に実装。`initialUnreadCount`(サイドバーの`unreadCount`)を基準に区切り位置のメッセージIDを一度だけ確定し、以降はビュー滞在中固定する。`initialUnreadCount`はサイドバー側の非同期取得に依存するため、直リンク等でメッセージ読み込みの方が先に終わる競合があり、これは専用effectで「メッセージ読み込み完了」と「未読件数到着」の両方を個別に待って解消した(実機確認で発見)。
- [x] 検索結果・通知からのジャンプ・ハイライト(該当メッセージを画面中央にスクロールし背景色フェードアウト。スレッド返信もジャンプ対象、S-07を自動的に開く)。**フェーズ9-D/9-Fの既知の制約(読み込み済み範囲外のスレッドへジャンプできない)を解消した。** バックエンドの`GET /messages/{id}/context`(前後ウィンドウ+`hasOlder`/`hasNewer`を返す、フェーズ8時点で実装済みだが未使用だったエンドポイント)を新規に呼び出し、対象が未読み込みの場合はメッセージ配列を丸ごと入れ替えてVirtuosoを再マウントする(`firstItemIndex`を初期値に戻し、`initialTopMostItemIndex`で直接ジャンプ先を指定。命令的`scrollToIndex`は再マウント直後だとVirtuoso自身の初期配置に負けて意図した位置に着地しないことを実機確認で発見し、propでの直接指定に変更した)。ウィンドウとライブ末尾の間にギャップが残る場合(`hasNewer`)はリアルタイム新着の追記を止め、「ジャンプ中・最新のメッセージに戻る」導線で復帰させる設計とした。
- [x] タブタイトルの未読件数 — `useUnreadTabTitle`(新規)。サイドバーの未読バッジと同じ「現ワークスペース内の未読メッセージ数」(チャンネル+DMの`unreadCount`合計)を使う(通知ベルの`unreadCount`はメンション・招待等の別概念のため混ぜない)。
- [x] (任意)ブラウザ通知 — Web Pushではなく簡易版(ブラウザ組み込みのNotification APIのみ)を選択。VAPID鍵管理・Push購読DB・Service Workerを伴う本格的なWeb Pushは、タブ/ブラウザを閉じていても届く一方で実装規模がフェーズ10の他項目と比べて大きいため見送り、既存のSTOMPリアルタイム通知をタブ非表示・非フォーカス時のみOS通知としても表示する設計とした(`lib/browserNotifications.ts`、`ProfileModal.tsx`にトグルUI)。タブを開いたまま他の作業をしている間のみ有効(ブラウザ/タブを閉じている間は届かない)。

### 先に書くテスト

このフェーズは主にUI機能のため、認可クリティカルテストの新規追加は無い。既存の受け入れテスト(AUTH-N10〜N17、AUTH-N27〜N29等)がUI経由でも成立することを手動確認する。

### 対象外(本フェーズでは扱わない)

- 音声通話等、CLAUDE.mdで対象外と明記された機能(ボイスチャンネル)

### 確認方法

```bash
cd apps/api-java && ./gradlew bootRun --args='--spring.profiles.active=dev,seed'
cd apps/web-next && pnpm --filter @chatspace/web-next dev
# 複数ブラウザタブで未読区切り線・検索/通知ジャンプ・タブタイトル未読件数・デスクトップ通知トグルを手動確認
# モバイル幅(390×844等)・デスクトップ幅(1280×800)の両方で回帰確認(9-Fで実装済みのレスポンシブ対応を崩していないこと)
```
